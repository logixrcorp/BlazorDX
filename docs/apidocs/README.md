# API reference (DocFX)

A generated API reference covering every public type and member across BlazorDX's ten
published packages — read directly from their XML doc comments via
[DocFX](https://dotnet.github.io/docfx/), so it can never drift from the shipped source.

This is deliberately separate from the interactive, per-component parameter reference
already embedded in the demo app (`/docs`, source in
`samples/BlazorDX.Demo/BlazorDX.Demo.Client/Pages/DocsHome.razor` +
`Docs/DxApiTable.razor`) — that one is scoped to `[Parameter]` properties on components a
visitor can also try live; this one is the full API surface (every public class, interface,
method, and property, including the non-component libraries like `BlazorDX.Interop` and
`BlazorDX.Security`), generated by a purpose-built tool rather than hand-maintained.

## Building locally

```bash
dotnet tool install -g docfx   # once
docfx metadata docs/apidocs/docfx.json   # compiles the target projects, extracts XML docs to docs/apidocs/api/
docfx build docs/apidocs/docfx.json      # renders the static site to docs/apidocs/_site/
docfx serve docs/apidocs/_site           # preview at http://localhost:8080
```

Both generated directories (`api/`, `_site/`) are gitignored — regenerated from source, not
committed.

**Gotcha:** `docfx metadata` compiles each target `.csproj` itself, which re-triggers that
project's own MSBuild targets — including `BlazorDX.Components`' `StageApiDocXml`
(`AfterTargets="CoreCompile"`), which copies its XML doc output to
`src/BlazorDX.Components/wwwroot/api-docs.xml` (the file the *in-app* docs at `/docs` read).
DocFX's own compilation pass isn't a full `dotnet build`, so this can produce a smaller,
incomplete `api-docs.xml` than a real build does. If `git status` shows that file changed
after running `docfx metadata` locally, run a real `dotnet build BlazorDX.slnx` afterward (or
just `git checkout -- src/BlazorDX.Components/wwwroot/api-docs.xml`) before committing —
don't commit whatever `docfx metadata` happened to leave there. CI is unaffected (its working
directory is discarded, never committed back).

## Hosting

`.github/workflows/docs.yml` builds and deploys this to **GitHub Pages** on every push to
`main`. That workflow only takes effect once GitHub Pages is enabled for this repository
(Settings → Pages → Source: **GitHub Actions**) — a one-time, repo-owner-only setting this
workflow file cannot flip on its own.

## Adding a package

Add its `.csproj` to the `metadata[0].src[0].files` array in `docfx.json`, then add a row to
the package table in `index.md`.
